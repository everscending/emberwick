EMBERWICK

A browser action RPG about a tiny red-panda knight carrying warmth into a world that is slowly going cold.

JavaScriptThree.jsWebGLViteGLB assets

TL;DR

  • This is already a real playable game foundation, not a scene mockup: movement, combat, quests, puzzles, enemies, progression, dialogue, checkpoints, inventory, and a seamless world are wired together.
  • The strongest work is the world identity: warm village crossroads, distinct regional moods, a memorable hero, strong combat animation, and environmental story beats.
  • The current build covers quests 1–4. The Ashen Keep finale, Ash Knight, audio, saving, title/chapter select, ending, and several secrets are not implemented.
  • The biggest demo risk is UX framing. The game opens directly into play with no logo, controls, onboarding, or audio, so judges must infer how to play.
  • The code is intentionally direct: one Three.js loop plus small domain modules, one runtime dependency, and no backend.

What is this, really?

EMBERWICK is a compact Zelda/Tunic-style adventure built for a game-week deadline. Elder Maren sends the hero to recover three Ember Shards while the Great Ember dies. The player clears the village well, wakes a forest stone circle, restores a beam through drowned ruins, survives a ritual in the Hollow Dark, and is meant to finish at the Ashen Keep.

The best analogy is a handmade tabletop adventure that happens to run in WebGL. There is one continuous board, the scenery is placed deliberately, roads and landforms guide you, and small state variables decide which chapter is active and which gates open. There is no server or database. Everything happens in the browser.

Built identity: the visual arc “warm → mysterious → sad → afraid → dead → reborn” is present in terrain colors, vegetation, particles, fog, landmarks, and lighting. Missing payoff: the final “reborn” beat does not exist yet because quest 5 and the ending are absent.

What it can actually do

Move and fight

WASD movement is screen-relative under a fixed isometric camera. The hero can slash, chain a side-slash/chop combo, roll with invulnerability frames, drink flasks, and later unlock a dash, charged spin, and ranged Ember Bolt. Hits trigger freeze-frame hit-stop, camera shake, sword trails, enemy flash, knockback, health bars, and slime splatter.

Explore one continuous world

The 220×220 world contains a village hub, Whispering Forest, Sunken Ruins, Hollow Dark, and Ashen Keep approach. A shared analytic height function drives both the visible terrain and entity placement. Deep water and cliffs block movement; a bridge and gated mouths define routes. A circular minimap shows terrain, landmarks, the player, and a pulsing objective.

Follow quests and solve puzzles

  1. Talk to Maren, clear four slimes near the old well, return for a skill point.
  2. Find Hermit Fen, touch five stones from shortest to tallest, collect shard one.
  3. Cross the stream, rotate three mirrors until the beam reaches the vault, examine three murals, collect shard two.
  4. Return for Maren’s lantern, enter the Hollow Dark, light braziers in bead-count order, defeat the Gravewarden, use its Bone Key, collect shard three.

The Keep is dressed as a location but has no glyph gate, boss, or completion sequence yet.

Use supporting systems

Dialogue freezes the world and types text onto the screen. Interactions select the closest nearby target. Hearth shrines heal, refill flasks, and set the respawn point. The skill panel offers three linear branches. The satchel records key items. Quest gates push the player back with an inner-monologue explanation instead of an invisible wall.

How the pieces fit together

The modules share a few live state objects—mainly player stats, quest state, enemies, interactables, and colliders. That is simple and appropriate for this deadline-sized game. The tradeoff is that a future save system must deliberately serialize each store.

Follow one action, start to finish

This traces the first quest interaction: walking to Elder Maren and pressing E.

  1. input.js records the E key as pressed for one frame.
  2. main.js calls updateInteract(player) while no menu or dialogue is open.
  3. interact.js finds the nearest in-range interactable and invokes Maren’s callback.
  4. npc.js calls the dialogue function registered for Maren, then sends its lines to say().
  5. quests.js changes quest 1 from not-started to active and supplies the well objective story.
  6. dialogue.js displays the lines while the main loop freezes combat and movement; hud.js then reflects the new objective.

Words you’ll see a lot

Three.js
The library that creates the scene, camera, meshes, lights, animation, and WebGL renderer.
Vite
The development server and production bundler. It does not define the game architecture.
Toon material
A stepped-lighting material that gives models the flat illustrated look.
Instancing
Drawing many copies of a tree or prop efficiently in fewer draw calls.
Interactable
A world position, radius, prompt, and callback activated with E.
Quest state
Small numeric flags for each quest plus shard and kill counters.
Gate
A circular progression boundary that opens when a quest or ability condition is true.
Hit-stop
A tiny pause on impact that makes attacks feel heavier.
Hearth shrine
A checkpoint that heals, refills flasks, and becomes the new respawn point.

Where to actually dig in

  1. Start with src/main.js. It shows every system that exists and the exact per-frame order.
  2. Read src/quests.js beside GAME_SPEC.md. That comparison exposes the implemented story spine and the remaining finale.
  3. Open src/player.js for the deepest piece of craft: the complete combat/animation state machine and hand-built red-panda rig.
  4. Use src/regions.js plus src/ground.js to understand the map and wayfinding.
  5. Inspect src/circle.js, src/ruins.js, and src/hollow.js for one self-contained example of each puzzle.
  6. Run npm run dev for local play or npm run build for dist/. The production build succeeds as of this snapshot.
